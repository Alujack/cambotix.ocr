# Security and privacy

National ID cards contain highly sensitive personal data. Local inference is
a strong starting point, but it does not make an integration secure by
itself.

## What the SDK does

| Commitment | How it is enforced |
| --- | --- |
| No network access during inference | The core package contains no HTTP client code. `tests/security/test_offline.py` blocks sockets and DNS during extraction and API calls. `tests/security/test_core_isolation.py` checks that the core never imports FastAPI or HTTP clients. |
| No silent model downloads | Bundles are installed only from a local path (`khmerocr models install --from`). A missing model raises `MODEL_NOT_AVAILABLE`. |
| Model integrity | Every bundle file is checked against its manifest SHA-256 before loading. |
| No document content in logs | The engine logs step names, error codes, counts, and timings only. Exception messages, which may echo text, are never logged. `tests/security/test_no_pii_in_logs.py` checks this at DEBUG level, including on failure paths. |
| No storage | Images are decoded in memory and never written by the engine. The API keeps multipart uploads in memory instead of spooling them to temporary files. |
| No telemetry | The SDK collects and sends nothing. |
| Human review | `review_required` is `true` whenever a critical field is missing, invalid, corrected, or below the confidence threshold; when image quality is degraded; when the card boundary was not found; and always while the layout template is unverified. |

### Known temporary files

The Tesseract backend (via `pytesseract`) hands each crop to the `tesseract`
process through a short-lived file in the system temp directory, deleted after
each call. On shared hosts, point `TMPDIR` at a private directory (for
example a tmpfs readable only by the service user). Backends that run
in-process do not have this limitation.

## Responsibilities of the integrating application

- Do not store source images or extracted fields unless you need them; if you
  do, encrypt them and define retention and deletion.
- Do not log API responses: they contain the extracted identity fields.
- Treat `review_required: true` as a hard stop for automated decisions.
- OCR does not establish that a document is authentic. KhmerOCR performs no
  biometric matching and no document verification.

## Development data

- Public fixtures are synthetic SPECIMEN cards with clearly fake values,
  generated by `khmerocr.testing.synthetic`.
- Real ID images require explicit authorization, minimal access, and an
  access-restricted evaluation environment. Locally, keep them under
  `benchmarks/data/private/` (git-ignored, mode 700) with their `labels.jsonl`. Never commit them to Git, test
  fixtures, or public benchmarks. Never run `benchmarks/evaluate.py
  --include-values` on real images.

## Local API exposure

The local API has no authentication. It binds to `127.0.0.1` by default; in
Docker, publish with `-p 127.0.0.1:8000:8000`. Do not expose it to a network.

## Future hosted service

The paid hosted API is a separate deployment and must add authentication,
rate limiting, TLS, strict tenant isolation, retention controls, and a
documented deletion policy. Obtain legal review of Cambodian privacy,
cybersecurity, and identity-document obligations before accepting production
ID data. Billing and authentication stay out of the OCR engine.
